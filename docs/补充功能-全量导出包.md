## 二、格式：单文件 `.tgbundle`（外层 ZIP 容器）

```
manifest.json               {"format":"tgbundle","formatVersion":1,"guides":[内层名…],"exportedAt":ISO时间}
001_<安全名>-<日期>.tgshare  第 1 篇标准 .tgshare（v8.0/v3 原片模式）
002_<安全名>-<日期>.tgshare  第 2 篇 …（中文标题允许进内层名——与单包命名同口径）
```

- **内层** = 单篇 `.tgshare`（v3 原片模式）：封面 + 标记插图 + 攻略内照片 + **账本归属照片/视频**（v8.1 注入口）全部原件字节直通（不缩放 / 不转码 / 不烧水印）；
- **外层**：内层条目以 `CompressionType.none` 存储（内层本身已是 ZIP，二次压缩零收益）；条目名带三位序号前缀防同名冲突；manifest 记内层清单；
- **显式不做攻略级指纹查重**（外层 `fingerprint: ''`）——查重逐条在内层导入时按 manifest 指纹比对；
- **不限制总体积**：1 GB 上限是单包分享的 UI 侧口径，全量包复用 `ShareService.originalCapBytes` 校验的路径完全跳过。媒体从磁盘流式写入（内存 O(1) 逐条，`Directory.systemTemp` 工作目录收口即清）。

## 三、导出弹窗（`full_export_sheet`）

入口：☰ 菜单「全量导出」→ 概览（共 n 篇 / 其中 m 篇挂有相册归属媒体，将一并打包）→ 进度（`正在打包第 k/n 篇：<标题>`，**可取消**——篇间与篇内逐项都响应）→ 完成（输出路径 + 总体积）。

- 输出经既有 `saveShareFileAt`（桌面=下载目录，优先改名搬运、失败回退复制，临时目录不留残留副本）；
- 产物名 `<t.bundleFileName>-<YYYYMMDD>.tgbundle`（zh：`AtmaPook_全量备份-20261023.tgbundle`）；
- Web 置灰（无文件系统——原片模式同口径）。空攻略本时「开始」禁用。

## 四、导入（恢复整本）

单一入口（「加载分享」按**扩展名分流**，类型选择器同步加 `.tgbundle`）：

1. 文件名以 `.tgbundle` 结尾 → 走全量包导入分支（**不进 1GB 上限校验**）；
2. `ZipDirectory.read` 只读中央目录（小）；校验外层 manifest（format / formatVersion / **条目白名单**——`manifest.json` + `NNN_*.tgshare` 之外的任何条目整包拒收）；
3. 逐条取出内层 `.tgshare`（archive 4.5 懒读取：文件后端字节视图，**同一时刻仅一个内层包驻留内存**——十几 GB 级大包内存安全）→ 照常 `parseShare` + `applyImport` + `addImported`；
4. 查重：逐条以包内 manifest 指纹比对 `hasShareKey`，命中**自动跳过**（不逐条弹窗——大包逐条确认会打断流程）；
5. 结果：成功 n · 重复 m · 失败 z 汇总 SnackBar（有成功导入即不弹失败框）；导入不像单包那样自动跳进攻略地图（整本恢复留在首页即可）；
6. 单包 `.tgshare` 流程零改动（1GB 上限 / 指纹弹窗询问 / 成功后 open 地图页）。

## 五、注意事项

- **大包建议桌面端导入**（移动端受内存与文件选择器限制；Web 不支持）；
- 导入只新增不覆盖（与既有口径一致；重复攻略自动跳过保证幂等）；
- 若同一设备既是导出端又是导入端（临时目录测试），guide.json 中账本归属照片将以「攻略内照片」形态复原（账本绑定关系不在分享链内——接收方地理相册不受影响，既有隔离口径不变）。
