## 一、需求与定位

分享时提供**两种打包模式**（`share_export_sheet` 顶部 SegmentedButton 分支选择）：

| 模式 | 口径 | 用途 |
|------|------|------|
| **水印低质版**（默认） | 照片 ≤960px q72、封面 ≤1280px、视频转 ≤720p，**全部烧录不可逆水印**（v6/v7 现行行为，零改动） | 发给朋友防泄底图 |
| **原片高清版**（v8.0 新增） | 照片/插图/封面/视频**按原件字节直接入包**：不缩放、不转码、不烧水印 | 共享原画质 / 永久备份（跨设备搬家链） |

硬性约束：
1. **包体上限 1 GB**（`ShareService.originalCapBytes`）；预估超限时提示「删除部分照片或降低照片质量」，提供**去筛选 / 降质打包（两档选一）**分流；
2. **全程不动原片**：原件文件只读；涉及降质时副本只在内存合成 / 落系统临时目录，打包完成即整体清除；
3. 接收侧隔离口径不变：原片包导入后同样 `shared=true`、媒体落 `pics/<新id>/shared/`、**不进接收方地理相册**；新增 `sharedOriginal=true` 标记（允许再导出）。

## 二、格式：`.tgshare` 升 v3

```jsonc
// manifest.json 新增/变化
{
  "format": "tgshare",
  "formatVersion": 3,          // v1=无视频旧包；v2=+videos/；v3=+policy（读取端 v1/v2/v3 双向兼容）
  "policy": "original",        // "watermarked"（缺省按水印版处理）/ "original"
  "watermarkText": "",         // 原片包恒空串（键保留，向 v1/v2 manifest 结构看齐）
  "fingerprint": "...",        // 不变：FNV-1a64(guide.json 剥离时间戳) + 视频锚段
  "counts": { "markers": …, "photos": …, "videos": …, "images": … }
}
```

**指纹跨模式一致**：同一攻略水印包与原片包的 `guide.json` 字节相同（`Guide.toJson` 不受模式影响）→ 指纹相同 → 接收端查重跨模式有效。配套铁律：`Guide.sharedOriginal` 与 `shareKey` 一样**按需序列化**（false 时不写 JSON），本地攻略的 guide.json 字节不因新字段变化，与 v6/v7 时期导出的指纹保持稳定。

**条目命名（原片模式）**：
- `photos/<photoId>.<原扩展名>`、`images/<mkId>_<n>.<原扩展名>`、`cover.<原扩展名>`——媒体内容是什么字节就什么名（jpg/jpeg/png/webp/gif 白名单内）；
- `videos/<videoId>.<原扩展名>`（mp4/mov/mkv/webm/avi/m4v 白名单内）；
- `thumbs/<id>.jpg`——缩略恒为 ≤256px 无水印 JPEG（复用原件已有的 ≤512px 缩略再降采样，速度最快）；
- **降质档生效时**：降质产物恒为 JPEG → 照片/插图/封面条目名随之改 `.jpg`（名与内容一致，避免"PNG 名 JPEG 内容"的误读）。

**白名单 v3**（`_entrySafe`）：`^(photos|thumbs|images)/<name>.(jpg|jpeg|png|webp|gif)$` + `^videos/<name>.(mp4|mov|mkv|webm|avi|m4v)$` + `^cover.(jpg|jpeg|png|webp|gif)$` + 信封三固定件；穿越（`../`）与非白名单扩展仍拒收。导入侧按候选扩展名探测条目（`_findEntry`，jpg 优先），落盘 rel 保留原扩展名。

## 三、1 GB 上限与超限分流（导出弹窗）

流程（`_run()`，仅原片模式）：

1. **实测预估** `estimateOriginalBytes`：逐条读磁盘文件字节求和（`Directory.systemTemp` 三件套 `share_temp.dart` 条件导入；内存存储自动回退字节长度）+ manifest/guide.json 8KB + 缩略 24KB/条常数；选项页实时显示「原片合计：X（上限 1GB）」；
2. 预估 > 1 GB → **超限弹窗**（标题「包体超出上限」）：
   - 文案：「原片包预计 X，超过 1 GB 上限。请剔除部分照片/视频，或选择下方降质档后按“降质打包”。」
   - **去筛选** → 打开内容勾选清单（照片 + 视频逐条 Checkbox，显示"已选 n/total"），剔除后回选项页重估，再次达标由用户手动按打包；
   - **降质打包** → 弹窗内 RadioGroup 二选一：
     - **高清优先**：长边 ≤2048 / JPEG q85；
     - **体积优先**：长边 ≤1080 / JPEG q80；
     选定后直接重跑打包（不再预估）。降质只作用于**本次打包副本**（内存解码→缩放→JPEG，无水印），原图文件不产生落盘副本、不被改动；
   - **取消** → 回选项页自行调整。

## 四、流式实现与残留规避（关键技术点）

原片包动辄数百 MB（视频原件），逐字节驻留内存不可行。实现（archive 4.5.2）：

- **输出侧**：`ZipEncoder.startEncode(OutputFileStream(tempZip, bufferSize: 1MB))` → ZIP 逐条写入系统临时目录（`Directory.systemTemp.createTemp('tgshare_orig_...')`），最后 `endEncode()`；
- **输入侧**：媒体原件经 `ArchiveFile.stream(name, InputFileStream(abs, bufferSize: 1MB))` + `CompressionType.none`（媒体已是压缩格式，deflate 只耗时无收益；尺寸优先两遍读由 encoder 分块完成，内存占用 O(1)）；条目添加后 `autoClose` 关流；
- **降质/缩略回退**：内存合成（`WatermarkComposer.compose(text: '')` 空水印路径），条目改 `ArchiveFile.bytes`；
- **文件系统不可用回退**：`storage.absolutePath` 抛 `UnsupportedError`（Web/`MemoryStorage` 测试桩）→ 自动回退内存字节直通，同一套 API 双端可用；
- **收口（无残留）**：`saveExported` 遇 `tempPath` 走 `saveShareFileAt`——优先 `File.rename`（同分区零拷贝），跨分区回退 copy+delete；完成回调再 `deleteTempWorkDir(workDir)` 整目录清除（失败/取消路径在 `finally` 内同样清除）。临时目录用 `Directory.systemTemp`（非 path_provider）：不依赖插件通道，flutter_test 单测与 isolate 内同样可用。

**Web 禁用**：降级存储（base64/会话内存）载不动原片——弹窗内「原片高清版」Segment 置灰 + 说明文案；服务层 `kIsWeb` 防御性兜底抛 `StateError`。

**无需 ffmpeg（额外红利）**：原片模式视频不走转码 → **Android 等无 ffmpeg 平台也能导出完整原片包**（水印视频包在这些平台仍不可用，口径不变）。

## 五、导入侧（applyImport）

- 接受 v1/v2/v3（版本判定 `1 ≤ vInt ≤ 3`）；`policy` 缺省按 `watermarked` 处理（旧包零感知）；
- 原片包导入 → `Guide(shared: true, sharedOriginal: true, shareKey: fingerprint)`；媒体按白名单扩展名落 `pics/<新id>/shared/<新ph>.<原扩展名>`；封面按 `cover.<ext>` 实际条目名落 `pics/<新id>/cover.<ext>`；
- 再次导出：`share_export_sheet` 对 shared/sharedOriginal 攻略本就无入口限制；watermarked 口径不变（打出的仍是水印副本），original 包可直接再打原片——**备份链可延续**；
- 重复导入同指纹文件仍按既有查重提示，不产生脏副本。

## 七、验收要点（运行验收清单）

1. 分享弹窗默认仍为「水印低质版」，行为与 v7 完全一致（回归无破坏）；
2. 切「原片高清版」：实测体积实时显示 → 打包 → 下载目录得到 `.tgshare`；接收端导入后照片/视频为原画质、无水印；
3. 原片包 > 1 GB：出现超限弹窗 → 「去筛选」可剔除条目重估；「降质打包」两档生效、包压回 1 GB 内（以视频为主的大包超出部分来自视频——视频不降质，必要时需回到筛选剔除视频）；
4. 导入原片包的攻略：不进地理相册（隔离口径）、照片查看器删除/再导出可用、可再次打包为原片；
5. 临时目录无残留（`%TEMP%/tgshare_orig_*` 打包完成后应被清除）；
6. Web 端：原片模式置灰，水印版功能不受影响。
