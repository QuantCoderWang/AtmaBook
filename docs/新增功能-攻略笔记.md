# 新增功能：攻略笔记（自动生成）— 设计文档 v1

> 状态：**已按本文档交付（v7.1，2026-10-22 验收通过）**——三轮口径修改记录见《功能点清单.md》「v7.1 攻略笔记」节。
> 核心定位：**纯派生视图**——不新增任何存储、不新增任何手写入口，全部信息实时抽取自攻略已有数据（Place 图文/照片/坐标/必去标记 + 片区聚类结果 + 住宿点）。

---

## 一、需求摘要（用户原文归纳）

在「攻略页面右上角三点菜单」中新增**攻略笔记**菜单：
- 按攻略内**片区**划分游览区域；
- 按**住宿位置与各片区中心的距离**排出游览先后（无住宿则按片区内游览点数多→少）；
- **多个住宿**：笔记顶部让用户选择哪个住宿作为游览起点；
- 片区内按**必去与否**排列景点，景点照片/坐标/图文直接抽取已登记数据，缺失标「暂缺」；
- **餐饮/购物**落在片区范围内 → 作为推荐附在片区信息最后，同样带照片/位置/图文，缺失标「暂缺」；
- 每个片区信息最上方带**范围标记（半径及实际覆盖公里数）**；
- **所有坐标位置可点击导航**；
- 顺带修复：导航默认打开的是**谷歌地图**，改默认**高德地图**（境内境外同理；手机端由系统弹出选择本就可用，本期仅改桌面默认）。

## 二、入口与 UI

| 项 | 方案 |
|---|---|
| 入口 | 攻略详情页（地图页）右上角 `⋮` 菜单新增一项「**攻略笔记**」（图标建议 `Icons.auto_stories` 或 `Icons.menu_book`） |
| 呈现 | **全屏页面**（内容长、需要滚动翻阅，弹层不合适） |
| 页头 | 攻略名 + 总览行（X 个片区 · Y 个景点 · Z 个住宿 · 地区标签） |
| 住宿选择器 | 攻略内住宿（`categoryId == hotel`）**≥2 个**时，页头下方出现住宿 chips（单选）：「以HotelA为游览起点」；**0/1 个住宿时不显示** |
| 切换住宿实时排序 | 点选立即按新起点重排片区顺序（纯内存计算，瞬时完成） |

## 三、数据来源（零新增存储）

| 笔记需要的信息 | 取自现有字段 |
|---|---|
| 片区划分 | `Guide.clusters`（M4 聚类结果，已随攻略 JSON 持久化，标记/参数变化自动重算） |
| 片区中心/半径/成员/孤立标记 | `ClusterZone.center / radiusMeters / memberIds / isolated` |
| 景点/餐饮/购物/住宿列表 | `Guide.markers`，按 `categoryId`（scenic / dining / shopping / hotel）分流 |
| 必去与否 | `Place.mustVisit` |
| 图文/照片/链接 | `Place.description / images / links`（`pics/<guideId>/` 相对路径，`MediaStore` 取字节） |
| 住宿→片区距离、实际跨度 | `haversineMeters`（`core/geo.dart`，聚类与就近归属已在用） |
| 攻略境内/境外 | `Guide.region`（影响导航措辞，不影响生成逻辑） |

**不做任何写入**：打开即算、退出即弃；攻略 JSON 增加一个字节都不发生。

## 四、片区划分与范围标记

- 直接采用现有聚类结果（DBSCAN，eps=片区半径、minPts=最少点数，用户可在设置页调整）；
- **孤立点片区**（低于最少点数的独立片区）同样展示，标注「孤立片区」；
- 未做聚类的旧攻略（clusters 为空）：打开笔记时**临时重算一次**（仅内存，不落库）；
- **片区大小标记**（每片区信息最顶部，两个数并列）：
  1. **设定半径**：该片区圈的 `radiusMeters`（如 `3.0 km`）——小片区/大片区一眼可辨的主依据；
  2. **实际跨度**：片区内成员点两两间最大直距 ≤ 2×半径，统一显示为 `跨度约 x.x km`（haversine 计算，成对比对取最大）。

## 五、游览顺序排序规则

```
若有住宿点（hotel 类标记 ≥1）：
    片区按「所选住宿 → 各片区中心」的 haversine 距离升序（近者先游）；
    住宿点自身展示为首个独立卡片「本次住宿」。
若住宿 ≥2 个：
    笔记顶部住宿选择器（默认选中第一个）；
    每个住宿 chip 上标注到攻略中心的概略距离，帮助用户判断。
若无住宿点：
    片区按「片区内游览点（必去+选去景点）数量」降序；
    并列时按片区中心到攻略全图质心的距离升序。
```
- 每个片区卡片头部同时显示「距起点 xx km」数值（住宿起点或列表首位片区为 0）；
- 排序纯展示层，**不回写**攻略 JSON（notes 顺序不持久化，与零存储原则一致）。

## 六、片区内容结构（单片区卡片，自上而下）

```
┌──────────────────────────────────────┐
│ 片区 N · 名称（孤立片区显示成员名）          │
│ 范围：半径 3.0 km · 跨度约 1.8 km        │ ← 大小标记
│ 距 起点/Hotel 2.4 km                   │
├──────────────────────────────────────┤
│ 🏞 景点（必去在前 → 选去在后；并列就近）    │
│   [照片] 名称 ★必去                    │
│   文字简介（无→「图文暂缺」）             │
│   📷 照片缩略（无→「暂无照片」）           │
│   📍坐标 30.1234,120.5678 [导航]        │ ← 全部坐标可点击导航
├──────────────────────────────────────┤
│ 🍽 餐饮推荐（在同片区圈内的 dining）       │
│ 🛍 购物推荐（在同片区圈内的 shopping）     │
│   结构同景点：照片/位置/图文，缺失标「暂缺」 │
└──────────────────────────────────────┘
```

- **餐饮/购物归片**：以「落在该片区圈内」为准（到片区中心距离 ≤ 片区有效半径）；同时落入多个圈的取**最近**者；
- 不落任何片区的餐饮/购物：汇总在笔记末尾「其他推荐」段；
- **住宿卡片**（有住宿时置顶）：住宿图文/照片/坐标/导航，结构同景点卡；
- 推荐路径遗址：本功能不生成数字路线（路线规划模块已移除），顺序即建议，如需导航逐点点击。

## 七、导航默认修复（与笔记并行落地的独立小改）

现状（`navigator_service.dart`）：桌面端写死 `google.com/maps`——**用户看到的谷歌就是这一行**。修改：

| 端 | 现状 | 修改后 |
|---|---|---|
| Windows 桌面 / Web | Google Maps 直链 | **高德地图** `https://uri.amap.com/navigation?to=lng,lat,名称&mode=car&coordinate=gaode&callnative=0`（浏览器即开即导航面板） |
| Android / iOS（未来） | `geo:` 系统选择（已会弹 App 选择器） | **不动**（符合「手机上会要求选择导航」） |
| 高德失败兜底 | — | OpenStreetMap 直链再失败 → 复制坐标（现有兜底保留，仅 Google 兜底移到高德之后顺位备选） |
| 境内/境外 | — | 默认同为高德（用户明确「境外同理」；境外靠 Web 高德数据尽力覆盖） |

笔记页面所有 📍 坐标按钮调用改后的 `NavigatorService.openPlace`，其余地图页/相册已有导航入口自动受益。

## 八、边界与空态

| 场景 | 行为 |
|---|---|
| 攻略无任何标记 | 笔记页空态：「尚无地点，先在地图上添加地点」 |
| 只有住宿没有景点 | 顶部住宿卡 + 空片区提示 |
| 景点无图文/照片 | 「图文暂缺」/「暂无照片」（按用户要求逐项标注，不隐藏占位） |
| 餐饮购物全在片外 | 归入末尾「其他推荐」；若也为空则该段不渲染 |
| 旧版无聚类数据 | 打开时临时 buildZones（必去点为准），不回写 |
| 境外攻略 | 排序逻辑完全一致（经纬度无关地界），导航走高德 Web |
| 超大攻略（>500 点） | 生成仅一次遍历 O(n²) 跨度计算，实测可接受；卡片懒加载照片（现有 MediaStore 缓存机制复用） |

## 九、实施拆解（预计两步走，各自独立可验收）

**Step A 导航修复（小）**
- `lib/services/navigator_service.dart`：桌面分支 Google → 高德 URI；兜底链调整。改完即可先验收（两点验证：任一地点点导航 → 浏览器打开高德）。

**Step B 攻略笔记（主体）**
1. `lib/services/guide_notes_service.dart`（新）：纯函数生成器——输入 Guide，输出 `NotesModel`（片区有序列表 + 各片区景点/餐饮/购物分组 + 距离/跨度/排序依据标注）；
2. `lib/core/geo.dart`：补一个 `boundingSpanMeters`（成员点两两最大直距）；
3. `lib/ui/notes/guide_notes_page.dart`（新）：页面 + 住宿选择器 + 片区卡片（复用现有主题色/字体、`MediaStore` 图片加载、Place 卡片样式尽量与地点列表一致）；
4. `lib/ui/guide/guide_map_page.dart`：三点菜单注册入口并传递攻略数据；
5. 测试：`test/guide_notes_test.dart`（排序规则 4 组：单住宿距离序 / 多住宿切换 / 无住宿数量序 / 餐饮购物归片与暂缺标注）。
- 全程不触碰存储层；`analyze` 0 + 67+ 项测试全绿 + `flutter run` 启动验收后收官。

## 十一、待你确认的口径（回复编号即可，例：「1 半径+跨度都要；2 默认第一个」…）

1. **片区大小标记**：按文档显示**两个数**（设定半径 + 实际跨度），还是只要其中一个？
2. **多住宿默认选中**：每次打开默认选**第一个住宿**（零存储、简单可预期），还是要成「距片区群中心最近者」？
3. **餐饮/购物全量展示**：片区圈内全部列出，还是只展示前 N 个（防超长）？
4. **导航出行方式**：默认**驾车**，还是要可选步行/公交（本期先固定驾车）？
5. 笔记是否需要**导出/分享**（如拼接成长图/文本）——建议本期不做，作为后续候选。
