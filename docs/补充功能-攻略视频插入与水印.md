本方案先审阅、后开发；与照片逻辑同理但每一步都有视频特有的技术决策，请重点看带 ⚠ 的分叉点。

## 一、数据模型（S1）

**复用 `Guide.photos` 列表 + `PhotoItem.kind` 字段**（不新建 VideoItem 类）：

```dart
/// PhotoItem 新增：
String kind;        // 'photo'（默认，旧数据兼容）/ 'video'
int durationMs;     // 视频时长（角标显示 mm:ss；照片恒 0）
```

- 绑定标记、片区归属、地图 GPS 照片层、排序/删除/重命名——**全部现有照片管线直接继承**，零改造；
- 照片数徽标（GlassChip）等统计处按 `kind == 'photo'` 过滤，视频不计入「照片数」。

**存储路径**：`pics/videos/v_<内容哈希>.mp4`（原图去重同 pin 图标策略）+ `pics/videos/thumbs/t_<hash>.jpg`（首帧缩略）。
⚠ 视频原图**不做缩放**——插入即按原文件入库（本地播放质量优先），降质只发生在分享导出时，与照片「本地原件 + 分享降质」策略一致。

## 二、导入（S1）

- 入口与照片完全一致：攻略照片页「添加」面板加一项 **「插入视频」**；
- 选文件：桌面 `file_selector`（过滤 mp4/mov/webm）；⚠ Android 照片导入现走 SAF/相册通道，视频暂用同一文件选择器扩展 MIME（`video/*`），若系统相册只回影内下载路径再补 SAF 分支；
- 后入库流程：复制原件到 `pics/videos/` → 提取首帧 → 生成缩略 → `addPhoto(kind:'video')`；
- **提取首帧/时长**（⚠ 平台分叉，本地解码不外发）：
  - **Windows**：随包附带 `ffmpeg.exe`（放 `windows/runner/ffmpeg/`，构建复制到运行目录；LGPL 源占用约 80MB，一次提取 -frames:v 1 全速）；
  - **Android**：`ffmpeg_kit_flutter_new`（LGPL 变体，Android 侧提取首帧 + 时长 + 后续转码用同一依赖，一举两得）；
  - 兜底：任何平台提取失败 → 渐变占位缩略（复用 PhotoThumb gradientIndex）+ durationMs 置 0。

## 三、播放（S2）

- 播放器选 **`media_kit` + `media_kit_video`**（⚠ 不用官方 `video_player`：其无 Windows 原生实现，而 media_kit Windows/Android 双端硬件解码成熟，字幕/倍速/进度亦开箱可用）；
- 新页 `VideoViewerPage`：点视频卡片进入——InteractiveViewer 缩放区替换为视频画面 + 底部播放控制条（进度/暂停/时长）+ 顶栏沿用照片查看器（名称/时间；只读模式用于相册账本场景同照片）；
- 卡片 UI：照片网格中视频显示首帧缩略 + **▶ 圆角角标 + 右下时长 chip**（PhotoMapBadge 同款白圈样式）。

## 四、分享导出（S3）——视频降质 + 水印

`.tgshare` 结构扩展（向后兼容）：

```
.zip/{manifest.json, guide.json, cover.jpg, photos/, thumbs/, images/, videos/}
videos/<videoId>.mp4      目标 ≤720p H.264 CRF~30 faststart + 全画面斜向平铺水印
thumb  照旧入 thumbs/     视频首帧缩略同照片规格（≤256px + 水印）
```

⚠ **水印生成方式（关键设计，与照片同一视觉）**：
不在 ffmpeg 里写 drawtext（旋转排版 + 中文字体路径三平台折腾易碎），
而是**复用 Dart 水印合成器**：导出时用与照片完全相同的 `watermark.dart` 45° 平铺逻辑，
在**透明画布上**绘制水印文字 → 编码为目标分辨率大小的水印 PNG → ffmpeg叠加一行 filter：

```
-i 原视频 -i overlay.png -filter_complex "[0:v]scale=-2:720[v0];[v0][1:v]overlay[v]" -c:v libx264 -crf 30 -movflags +faststart
```

- 优点：水印排版/角度/透明度与照片**逐像素同源**（改一处参数两端同步），ffmpeg 只做缩放+叠加+编码，命令简单可靠；
- ⚠ 中文字体：水印文字由 Flutter 引擎绘制（与照片同等权限），**ffmpeg 无需字体**——规避 drawtext 中文字体痛点；
- Android 同样用 ffmpeg_kit_flutter_new 执行同一命令字符串；
- 进度/取消：导出弹窗加视频阶段文字（复用现有进度弹窗样式），ffmpeg 转码各大致几秒~几十秒/段；
- 音频直接 `-c:a aac -b:a 96k`（不处理水印——画面水印已是防滥用重点）。

**导出选项**：分享页加「视频压缩 + 水印」开关（默认开）；
关闭则视频同样导出（原样复制，仅出水印 PNG 预览禁用）⚠ 默认锁定与照片相同三默策略：不可免水印，只可降质参数不动。

## 八、Android 接入评估（S4，方案记录——不随 v7.0 实装）

> 结论：**可行且延后**。接到 Android 构建/发布阶段再做；本节预写全部决策点，届时照单施工。

**1. 依赖与变体**：`ffmpeg_kit_flutter_new`（原 arthenica 官方包 2025 年停止维护后的社区续命版）。
必须选 **full-gpl 变体**——LGPL 变体同样不含 libx264（Windows 首轮已踩过一遍：`Encoder not found`）。

**2. 命令与 API 映射**（与服务端代码一一对应）：

| 本应用调用点 | Windows 现实现 | Android（ffmpeg_kit）等价 |
|---|---|---|
| 时长/分辨率探测 | ffprobe 子进程 CSV | `FFprobeKit.getMediaInformation(path)` → `information.getDuration()` / streams 的 width/height |
| 首帧提取 / 转码+水印 | Process.run/Process.start + 参数列表 | `FFmpegKit.executeWithArguments(List<String>)` **务必用参数列表形式**（避免把整条命令拼成字符串时的滤镜转义陷阱） |
| 进度回调 | `-progress pipe:1` 解析 `out_time_ms` | `executeWithArgumentsAsync(args, completeCallback, logCallback, statisticsCallback)`，`statistics.getTime()` 直接给秒数 → 与总时长折算 frac |
| 取消 | kill 进程 | `FFmpegKit.cancel(sessionId)` |

Windows 修行记录全部沿用：滤镜表达式内逗号 `\,` 转义、`-aac_coder fast`（kit 构建若无此缺陷，该参数也无害）、GPL 变体含 libx264。⚠ `-hwaccel auto` 在 kit 通用构建里**不可假定有效**（其解码多用 mediacodec 专用解码器名或回退软解）——Android 旗舰软解 4K H.264 也能接受，实机测后定夺是否调 `-c:v h264_mediacodec` 编码路线。

**3. 存储与策略不变**：临时工作区在应用私有目录，读毕即删；**绝不写系统相册原文件元数据**；导入落地为攻略内条目不进地理相册。

**4. 体积影响**：full-gpl 变体按 ABI 增加 ~25–35MB/包——与「仅核心代码、不带安装包」交付口径一致，留待打包阶段权衡（可用 ABI 拆分/split per abi 缓解）。

**5. 工作量预估**：0.5–1 人日（接入 + 双命令验证 + 真机 4K/1080p 素材回归）；判定 FAIL 的回退路径：Android 侧仅做**首帧/时长提取**（软化版分享——视频条目导出时跳过并计入 skipped，旧包兼容逻辑已天然支持）。
